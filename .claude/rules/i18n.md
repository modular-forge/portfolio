# Localization (Angular built-in i18n)

English (`en`) is the source locale and Spanish (`es`) the translation, one prerendered build per
locale. Decisions live in OpenSpec (`site-localization`); these are the working rules.

- Mark visible text in templates with `i18n="meaning|description"` (attributes: `i18n-title`,
  `i18n-aria-label`, …) and in TypeScript with `$localize` `:meaning|description:text`. Always give
  both parts. IDs are Angular's default hashes, so changing the English text or its meaning gives
  the unit a new ID that needs a new translation.
- Add or change a text: write the English with its marker, run `npm run extract-i18n` (new units
  arrive without a translation, removed units are deleted, existing translations are kept), then
  translate the units that `npm run i18n:check` lists in `src/locale/messages.es.xlf`: fill
  `<target>` and set `state="translated"`. A target that repeats the English still passes, so
  translate it. Skipping `extract-i18n` makes the build fail with `No translation found for "<id>"`.
- `i18n:check` fails on a unit with no `<target>`, an empty one or any other state than
  `translated`, `signed-off` or `final`. The production build fails on a text missing from the
  translation file and on a duplicate unit (`i18nMissingTranslation` and `i18nDuplicateTranslation`
  set to `error`).
- Each locale is served under its prefix: `/en/<path>` and `/es/<path>`; the build sets each
  locale's `<base href>` to its prefix. Links inside a locale use `routerLink` without the prefix
  (`/projects`, not `/en/projects`); a plain `<a href="/projects">` would lose the prefix. Only
  links to another locale use `localeUrl()` from `src/app/i18n/locales.ts`, as a plain `href` (the
  switcher does; the metadata uses `absoluteLocaleUrl()`).
- The hosting sends the root `/` to a locale by the browser's `Accept-Language`. That redirect is
  configured outside this repository: the build has no root `index.html`, only the two locale
  folders, so `/` is a 404 until the hosting redirects it.
- The language switcher (`src/app/i18n/language-switcher/`) is a plain link to the same page in the
  other locale. It stores no preference.
- `PageMetadata` (`src/app/i18n/page-metadata.ts`) sets the title, meta description, canonical and
  the `hreflang` alternates (`en`, `es`, `x-default`) on every navigation. `<html lang>` comes from
  the build.
- Typed data files store each visible text as `{ en, es }`, read through `LOCALE_ID`. A missing
  language fails to compile.
